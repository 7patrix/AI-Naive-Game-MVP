# v7 · 对话键盘操作小修

在 v6 第一夜基线上只改对话操作与灯油确认，没有新剧情、资源、美术或等待。v6 源码/完整回退包保持独立保留。

对话打开时聚焦安全选项：有关闭/取消就选它，其次选只读话题。只有单个领取/交付动作的页面会聚焦该动作，也必须新按一次 Enter 才执行。结局默认选继续留在镇里，不默认重玩。焦点有两像素金色边框。↑↓ 与 Tab/Shift Tab 在本页按钮间循环，Enter 执行，E/Esc 关闭，PgUp/PgDn 滚动正文；底部显示实际键位。模态框打开时背景 HUD 按钮不进入焦点循环。

输入在 GUI 按钮处理前统一消费。按住键、系统重复和未松开的重复 keydown 不会执行下一页动作；新页面若仍有激活键按下，要先松开再重新按。Space 不执行剧情动作。页面回调有代次检查，关闭、重建或执行动作后，旧按钮回调失效。窗口失焦会清理按键记录，避免失去 keyup 后卡住。

灯油流程为路线选择 → 最终确认。选路线时两份油仍完整；最终确认明示耗尽两份与另一条路熄灯。两个页面默认都是取消/返回，E/Esc 均不消耗。确认只接受当前待确认的路线，提交后原有油量/阶段保护阻止重复消费。

`scripts/dialog_input_qa.gd` 发送实际 InputEventKey/InputEventMouseButton，检查鼠标点击、键盘导航、按住输入、关闭/重入、双语重建、暂停、窄窗焦点、取消、两结局及真实场景重载。灯油 UI 测试使用准备就绪状态夹具；独立 `first_night_qa.gd` 仍走实际三居民/送药/修钟的全部流程，避免将 UI 夹具误称为完整玩法验证。

自动输入测试显式刷新事件缓冲并跨渲染帧检查，避免 Web 低帧率下多个物理帧内的按下/释放尚未送达 UI 就断言。游戏本身保持默认输入缓冲设置。依据 [Godot Input 官方文档](https://docs.godotengine.org/en/stable/classes/class_input.html#class-input-method-flush-buffered-events)，刷新只用于测试事件的明确时序。

当前证据保存在 `evidence/dialog_v7/`，旧 v6 实机录像与回执继续保留。精确检查计数、导出结果和 v6 备份校验见 `validation_summary.json`。运行方式仍为 `Start-MoonKiller.ps1` / `exports/windows/MoonKiller.exe`，正常 Web 为 http://127.0.0.1:8765/index.html 。

收尾已恢复并完成：Web 全剧情 111 项、对话输入 66 项均通过，完整控制台记录已保存。正常 Web 入口使用空 QA 参数，1280×800 截图已核验；浏览器真实按键走到公告牌，核验按住 E/重复输入、松开后关闭、Tab 焦点、Enter、Esc 暂停恢复和 720×540 显示。最新 Windows 导出包启动退出码 0，正常原生窗口也输出就绪日志。可见窗口启动后已关闭，本地 HTTP 试玩入口仍可用。
