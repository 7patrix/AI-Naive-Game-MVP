## 已识别的限制与未测项

- S3 删除本身失败时仍可能留下孤立密文对象：用例确认会报警、返回失败且不会创建公开作品。不能把“尝试清理”表述为存储故障下保证删除；需要测试桶故障演练和对账清理。
- 并发与回滚在内存 mock 的锁/事务模型中验证，不等于真实 PostgreSQL 隔离、死锁、连接池或锁超时验证。S3 预检也不能保证之后对象永远可读。
- 不加载真实 Godot 工程。PATH 及少量常见安装目录未发现 Godot 可执行文件，未下载软件；不据此断言整台机器绝对没有其他安装。
- VM 加载夹具没有验证浏览器 GPU、音频 worklet 执行、触控、全屏、跨站 Cookie 或 IndexedDB 存档。它只能证明多文件资源路由和 mock 启动消息链路。
- 实际模型调用、BullMQ 队列执行、正式数据库迁移、真实 S3、通配域名/TLS/代理、真实导出包的发布耗时和备份恢复仍未测。

后续必要输入：实际 Godot 版本与完整 Web ZIP、预期包大小、可操作的隔离 PostgreSQL/S3 环境，以及资源域名与 HTTPS 路由方案。密钥在本机或秘密管理系统注入，不通过聊天提供。
